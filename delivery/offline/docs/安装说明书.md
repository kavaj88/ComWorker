# ComWorker 安装与升级说明书

适用安装包：`ComWorker-__COMWORKER_VERSION__-offline-amd64.zip`

## 一、安装

### 1. 安装前准备

- Linux x86_64：Docker Engine、Docker Compose v2。
- Windows 10/11 x86_64：Docker Desktop，使用 Linux containers。
- 建议配置：4 核 CPU、8 GB 内存、20 GB 可用磁盘。
- 默认端口：客户端 `3000`，管理端 `3081`。

### 2. Linux 安装

```bash
# 校验安装包；下面的校验值文件须与 ZIP 放在同一目录
sha256sum -c ComWorker-__COMWORKER_VERSION__-offline-amd64.zip.sha256

# 解压安装包
unzip ComWorker-__COMWORKER_VERSION__-offline-amd64.zip

# 进入解压后的安装目录
cd ComWorker-__COMWORKER_VERSION__-offline-amd64

# 添加执行权限
chmod +x install.sh comworker.sh

# 首次安装；自动校验文件、导入镜像、生成密码并启动服务
./install.sh
```

### 3. Windows 安装

```powershell
# 校验安装包；将下面的 <SHA256> 替换为 ZIP 同目录 .sha256 文件中的值
(Get-FileHash .\ComWorker-__COMWORKER_VERSION__-offline-amd64.zip -Algorithm SHA256).Hash

# 解压安装包
Expand-Archive .\ComWorker-__COMWORKER_VERSION__-offline-amd64.zip -DestinationPath .

# 进入解压后的安装目录
Set-Location .\ComWorker-__COMWORKER_VERSION__-offline-amd64

# 首次安装
.\安装.bat
```

也可在 PowerShell 中安装：

```powershell
# 首次安装
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

### 4. 首次登录

```text
客户端：http://服务器IP:3000
管理端：http://服务器IP:3081
管理员：admin
初始密码：安装完成时显示，同时保存在 secrets/admin_password
```

登录管理端后，按页面提示修改管理员初始密码，再配置模型、用户、技能和连接器。

### 5. 修改安装端口

首次安装前编辑 `.env.example`，已安装后编辑 `.env`：

```dotenv
# 客户端端口
COMWORKER_CLIENT_PORT=3000

# 管理端端口
COMWORKER_MANAGE_PORT=3081
```

修改已安装环境的端口后执行：

```bash
# Linux：重新创建服务以应用端口
./comworker.sh stop
./comworker.sh start
```

```powershell
# Windows：重新创建服务以应用端口
.\comworker.ps1 stop
.\comworker.ps1 start
```

## 二、升级

升级前先解压新版本安装包，不要覆盖或删除旧版本目录。

### 1. Linux：从旧版本目录升级

```bash
# 进入旧版本安装目录
cd /opt/ComWorker-旧版本

# 指向已解压的新版本目录；命令会先完整备份，再启动新版本
./comworker.sh upgrade /opt/ComWorker-__COMWORKER_VERSION__-offline-amd64
```

### 2. Linux：从新版本目录升级

```bash
# 进入新版本安装目录
cd /opt/ComWorker-__COMWORKER_VERSION__-offline-amd64

# 添加执行权限
chmod +x install.sh comworker.sh

# 指向旧版本目录；命令会复制原配置和密钥，先备份，再启动新版本
./install.sh --upgrade-from /opt/ComWorker-旧版本
```

### 3. Windows：从旧版本目录升级

```powershell
# 进入旧版本安装目录
Set-Location C:\ComWorker-旧版本

# 指向已解压的新版本目录；命令会先完整备份，再启动新版本
.\comworker.ps1 upgrade -PackagePath C:\ComWorker-__COMWORKER_VERSION__-offline-amd64
```

### 4. Windows：从新版本目录升级

```powershell
# 进入新版本安装目录
Set-Location C:\ComWorker-__COMWORKER_VERSION__-offline-amd64

# 指向旧版本目录；命令会复制原配置和密钥，先备份，再启动新版本
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -UpgradeFrom C:\ComWorker-旧版本
```

升级完成后保留旧版本目录、旧镜像和升级前备份；确认业务正常后再自行归档。

## 三、备份、恢复与回滚

### 1. 手工备份

```bash
# Linux：备份数据库、配置、密钥、平台文件、技能和用户运行时数据
./comworker.sh backup
```

```powershell
# Windows：备份数据库、配置、密钥、平台文件、技能和用户运行时数据
.\comworker.ps1 backup
```

备份保存在当前安装目录的 `backups/backup-日期时间/`。

### 2. 恢复当前版本

```bash
# Linux：恢复指定备份；按提示输入 RESTORE
./comworker.sh restore ./backups/backup-YYYYMMDD-HHMMSS
```

```powershell
# Windows：恢复指定备份；按提示输入 RESTORE
.\comworker.ps1 restore -BackupPath .\backups\backup-YYYYMMDD-HHMMSS
```

### 3. 回滚到升级前版本

```bash
# Linux：恢复升级前备份并启动备份记录中的旧版本；按提示输入 RESTORE
./comworker.sh rollback ./backups/backup-YYYYMMDD-HHMMSS
```

```powershell
# Windows：恢复升级前备份并启动备份记录中的旧版本；按提示输入 RESTORE
.\comworker.ps1 rollback -BackupPath .\backups\backup-YYYYMMDD-HHMMSS
```

## 四、日常运维

| 操作 | Linux | Windows |
| --- | --- | --- |
| 查看状态 | `./comworker.sh status` | `.\comworker.ps1 status` |
| 查看日志 | `./comworker.sh logs` | `.\comworker.ps1 logs` |
| 启动 | `./comworker.sh start` | `.\comworker.ps1 start` |
| 停止 | `./comworker.sh stop` | `.\comworker.ps1 stop` |
| 重启 | `./comworker.sh restart` | `.\comworker.ps1 restart` |
| 保留数据卸载 | `./comworker.sh uninstall` | `.\comworker.ps1 uninstall` |
| 删除全部数据 | `./comworker.sh uninstall --purge` | `.\comworker.ps1 uninstall -Purge` |

删除全部数据时必须按提示输入 `DELETE`。

## 五、网络设置

- 对外仅放行客户端端口 `3000` 和管理端端口 `3081`，或 `.env` 中修改后的端口。
- 不要对外开放 PostgreSQL、网关和用户运行时容器端口。
- 公网部署时，在 ComWorker 前配置 HTTPS 反向代理。
- 使用云模型、OAuth 连接器或外部技能时，服务器需要访问相应服务域名。

## 六、故障处理

### Docker 未启动

```bash
# Linux：检查 Docker
docker info
docker compose version
```

```powershell
# Windows：检查 Docker Desktop 和 Compose
docker info
docker compose version
```

### 页面无法访问

```bash
# Linux：查看容器状态和日志
./comworker.sh status
./comworker.sh logs
```

```powershell
# Windows：查看容器状态和日志
.\comworker.ps1 status
.\comworker.ps1 logs
```

检查服务器防火墙、`.env` 端口和 Docker Desktop 的 Linux containers 状态。

### 安装包校验失败

重新复制 ZIP 和 `.sha256` 文件并再次校验，不要继续安装。

### 检测到已有数据卷但没有安装记录

升级时使用本说明书“二、升级”的命令。只有确认当前目录中的 `.env` 和 `secrets/` 属于该数据卷时，才执行：

```bash
# Linux：接管本机原安装
./install.sh --adopt-existing
```

```powershell
# Windows：接管本机原安装
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -AdoptExisting
```

### 忘记管理员密码

在能登录服务器的安装目录执行（需要 ComWorker 正在运行）：

```bash
# Linux：生成新的随机管理员密码
./comworker.sh reset-admin-password
```

```powershell
# Windows：生成新的随机管理员密码
.\comworker.ps1 reset-admin-password
```

命令会生成一个新的随机管理员密码，保存到安装目录的 `secrets/admin_password`，并强制管理员下次登录时修改。如需自行指定密码，可追加参数：

```bash
./comworker.sh reset-admin-password <新密码>
```

## 七、分卷安装包合并

安装包按 3 卷分发：`ComWorker-__COMWORKER_VERSION__-offline-amd64.part001`、`part002`、`part003`。先把三卷按顺序拼接为 ZIP，再按“一、安装”操作。

```bash
# Linux / macOS：按编号顺序拼接分卷
cat ComWorker-__COMWORKER_VERSION__-offline-amd64.part001 \
    ComWorker-__COMWORKER_VERSION__-offline-amd64.part002 \
    ComWorker-__COMWORKER_VERSION__-offline-amd64.part003 \
    > ComWorker-__COMWORKER_VERSION__-offline-amd64.zip
```

```powershell
# Windows PowerShell：按编号顺序拼接分卷
$part = "ComWorker-__COMWORKER_VERSION__-offline-amd64"
Get-Content $part.part001, $part.part002, $part.part003 -Raw | Set-Content -Encoding Byte "$part.zip"
```

```cmd
:: Windows CMD：按编号顺序拼接分卷
copy /b ComWorker-__COMWORKER_VERSION__-offline-amd64.part001+ComWorker-__COMWORKER_VERSION__-offline-amd64.part002+ComWorker-__COMWORKER_VERSION__-offline-amd64.part003 ComWorker-__COMWORKER_VERSION__-offline-amd64.zip
```

合并后若目录下有对应的 `.zip.sha256` 校验文件，可先校验再安装：

```bash
sha256sum -c ComWorker-__COMWORKER_VERSION__-offline-amd64.zip.sha256
```

## 九、已知限制

- 安装包体积较大（约 2.6 GB），请预留至少 20 GB 可用磁盘。
- 升级会先自动完整备份，升级过程中请勿中断；回滚会恢复到升级前备份所记录的旧版本目录与镜像。
- 当前版本不提供跨大版本的数据库自动迁移工具。若从较早版本升级，请先备份，并联系技术支持确认数据库结构兼容性。
- 备份文件包含数据库与全部用户数据卷，请妥善保管，避免泄露。
