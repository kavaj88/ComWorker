# ComWorker 对外交付与上线操作指南（不交付源码）

> 适用场景：把 ComWorker 作为**成品**卖给客户使用，只交付可运行的镜像与极薄配置包，**不交付任何业务源码**。

---

## 0. 核心结论

本产品已具备"只交付镜像、不交付源码"的能力。你（厂商）在自有构建机上把 5 个镜像构建好并推到镜像仓库（或导出为离线包）；客户侧只需要一份**极薄的配置包**（compose 文件 + 脚本 + 说明），即可在 Docker 上把整套系统跑起来。**源码、构建过程、你自己的密钥都不离开你的环境。**

两种交付方式：

- **方式 A · 私有镜像仓库（推荐，客户服务器能联网）**：`push_to_registry.sh` 推送 + 客户 `docker compose pull`
- **方式 B · 离线交付（内网隔离 / 无外网）**：`offline_deploy.py pack` 出 tar 包 → 拷贝 → `docker load` + 启动

## 1. 交付物清单（给客户 vs 不给客户）

### 1.1 必须给客户（不含任何源码）

```
comworker-delivery/                 # 一个文件夹，整体打包发给客户
├── docker-compose.yml              # 编排主文件（仅编排，无源码）
├── docker-compose.registry.yml     # 镜像拉取覆盖文件（方式 A / 离线复用）
├── .env.example                    # 配置模板（客户据此生成自己的 .env）
├── tools/
│   ├── gen_secrets.sh              # 生成 jwt_secret / model_keys_master_key
│   └── rotate_secret.sh           # 轮换单个 secret
├── LICENSE                         # 你的商业许可 / EULA（见第 6 节）
├── README.md                       # 用户使用手册（已存在，面向终端用户）
├── SECURITY.md                     # 安全说明（已存在）
└── 对外交付与上线指南.md           # 本文件
```

> 以上文件都是"壳"：compose 里用 `image:` 拉取，脚本只生成本地 secret，**没有任何业务源码**。

### 1.2 绝对不要给客户

- `platform/`、`cca-front/src`、`manage_front/`、`hermes-agent/`（源代码）
- `.env`（你本地含真实密钥的配置）——客户应自己从 `.env.example` 生成
- `secrets/`（你本地生成的密钥文件）
- `uv.lock`、`pyproject.toml`、`tests/`、`*.yaml` 测试数据等开发产物

### 1.3 镜像清单（你推到仓库 / 打进 tar 的）

| 镜像 | 内容 |
| --- | --- |
| `comworker-gateway` | 后端 API（FastAPI） |
| `comworker-manage` | 管理后台（Next.js 生产构建） |
| `comworker-cca-front` | 客户端（nginx 静态 + 反代，生产） |
| `comworker-hermes-agent` | 运行时沙箱（bridge 镜像） |
| `comworker-postgres` | Postgres 16-alpine（基础镜像重标签） |

## 2. 方式 A：私有镜像仓库交付（推荐，有网）

### 2.1 你侧（构建 + 推送，一次）

```bash
# 1. 登录你的私有仓库（阿里云 ACR / 腾讯 TCR / 自建 Harbor…）
docker login registry.cn-xxx.aliyuncs.com

# 2. 一条命令构建并推送全部镜像
COMWORKER_REGISTRY=registry.cn-xxx.aliyuncs.com/your-namespace \
COMWORKER_TAG=1.0.0 \
bash push_to_registry.sh
```

脚本会自动：构建 gateway / manage / cca-front / hermes → 拉取并打标签 postgres → 全部推送到 `$REGISTRY`。

### 2.2 客户侧（拉取 + 启动）

把第 1.1 节的配置包发给客户，客户执行：

```bash
cd comworker-delivery
export COMWORKER_REGISTRY=registry.cn-xxx.aliyuncs.com/your-namespace
export COMWORKER_TAG=1.0.0

# 1. 生成自己的密钥（jwt_secret / model_keys_master_key；admin 密码留空由系统生成）
bash tools/gen_secrets.sh

# 2. 拉取镜像
docker compose -f docker-compose.yml -f docker-compose.registry.yml pull

# 3. 启动
docker compose -f docker-compose.yml -f docker-compose.registry.yml up -d

# 4. 拿到初始管理员密码（首次启动打印在日志里）
docker logs comworker-gateway | grep -A6 'INITIAL ADMIN'
```

启动后访问地址：

- 管理后台：http://<服务器IP>:3081
- 客户端：http://<服务器IP>:3000
- 网关（一般对内）：http://<服务器IP>:8080

## 3. 方式 B：离线交付（内网隔离 / 无外网）

### 3.1 你侧（有网的构建机）

```bash
# 构建全部镜像并导出为单个 tar 包（--host 指定客户服务器 IP，用于前端写死 API 地址）
python offline_deploy.py pack --host 192.168.1.100
# 产物：comworker-images.tar（含 5 个镜像）
```

把 `comworker-images.tar` + 第 1.1 节的配置包（**不含源码**）拷贝到客户服务器。

### 3.2 客户侧（目标服务器）

```bash
cd comworker-delivery
docker load -i comworker-images.tar          # 导入镜像

# 关键：把导入的镜像按 registry 覆盖文件里的全限定名打标签，
# 这样可直接复用 docker-compose.registry.yml（无需 build、无源码）
docker tag comworker-gateway:latest      $REG/comworker-gateway:latest
docker tag comworker-manage:latest       $REG/comworker-manage:latest
docker tag comworker-cca-front:latest    $REG/comworker-cca-front:latest
docker tag comworker-hermes-agent:latest $REG/comworker-hermes-agent:latest
docker tag postgres:16-alpine            $REG/comworker-postgres:16-alpine

bash tools/gen_secrets.sh
docker compose -f docker-compose.yml -f docker-compose.registry.yml up -d
docker logs comworker-gateway | grep -A6 'INITIAL ADMIN'
```

> ⚠ 注意：`offline_deploy.py deploy` 默认用的是带 `build:` 的主 compose（会试图从源码重建），**不适合"不交源码"场景**。改用上面的「load + tag + registry 覆盖」流程即可彻底避开源码。

## 4. 首次启动后的「空产品」初始化（卖点）

系统启动后是**空的**：没有模型 key、没有用户、没有技能绑定。全部由客户自己配置：

1. 用日志里的初始管理员账号（`admin` / 自动生成的强密码）登录管理后台 :3081。
2. 触发初始化向导（Setup Wizard）：
   - **强制**：修改管理员密码（不改密，admin 路由会被拦截）。
   - **可选（推荐）**：在「模型管理」配置模型供应商 key —— 可跳过，稍后配。
3. 管理员在后台创建用户、配置模型、开放技能 / 连接器。
4. 用户登录客户端 :3000，按需配置自己的模型 key 即可对话。

> 模型 key 在数据库里用 Fernet（AES-128-CBC + HMAC）加密存储，不在磁盘明文、不进镜像。

## 5. 安全与运维要点

- **密钥不进镜像**：`jwt_secret` / `model_keys_master_key` 通过 file-based docker secret（`./secrets/`）注入，客户每台机器各自生成，互不相同。
- **轮换**：`bash tools/rotate_secret.sh jwt_secret` 可单独轮换；⚠ 轮换 `model_keys_master_key` 会使已加密的模型 key 全部失效，需在后台重填。
- **数据持久化**：Postgres 数据在 `comworker-data` 卷，备份即备份该卷；密钥文件 `secrets/` 也需单独备份。
- **升级**：你推新 `TAG`，客户改 `COMWORKER_TAG` 后 `pull` + `up -d` 即可。
- **端口暴露**：对外只暴露 3081（后台）和 3000（客户端）；15432（postgres）仅内网 / 调试用，勿公网暴露。
